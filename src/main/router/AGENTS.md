# RouterAgent 模块

- 实施依据为已确认的 `docs/router-agent-review-2026-11-06/technical-final.xml` 与七个增量设计状态。
- `controller.ts` 协调固定 Session、持久请求、查询、分配与恢复；业务身份和执行仍归原 Store／Orchestrator。
- `database.ts`、`store.ts`、`worker.ts` 负责后台 SQLite 请求、候选索引和项目记忆共用存储，不在主线程做数据库查询。停止 global_memory 接口及专属候选提取，保留项目记忆、需求上下文和历史表，不迁移或删除历史数据。
- Router 输入图片草稿复用 worker 与已有 `router_meta` 键值存储，保存图片附件元数据及预览，不新增数据库表；恢复期间保留编辑与添加能力，发送等待图片草稿读取完成。删除和发送成功只清理草稿记录，不删除原图；失败及后来新增的图片保留，图片预览不进入文本 localStorage 或 Agent 附件字段。
- `mcp.ts` 只提供带会话能力令牌的只读路由查询与专用分配入口；原始输入由宿主绑定，模型不得修改。
- 运行配置默认关闭；只有实际支持图片、原生会话与路由 MCP 注入的 Agent 配置才能启用。当前接通 DeepSeek Harness Web、Codex app-server、Claude SDK、Qoder SDK 与 TraeX exec。按用户于 2026-11-12 的最新要求，Router 沿用所选 Agent 的全部正常工具、MCP、Skills 和原生配置，额外注入路由工具；不再设置 Router 专用工具白名单、禁用内置工具或隔离本机 MCP。职责通过系统提示词约束：可阅读飞书、文件等资料以理解输入，完成归属判断后必须通过 router_assign_task 提交分配，业务执行交给目标任务。路由请求身份、版本校验及投递防重仍由宿主负责。TraeX exec／exec resume 继续复用本机程序、原生配置、登录态、会话和图片，不强制覆盖模型工具模式。其它接入尚缺原生会话或路由 MCP 注入能力时，明确说明实际缺项。
- 用户已确认扩展到可接收图片的 Agent。切换 Agent 时创建新的底层 Session，RouterAgent 页面保留连续历史，并持久保存 Agent 切换分界线；切回旧 Agent 也创建新 Session。分配期间立即保存新配置，当前分配继续使用原配置与工具资格，下一项尚未开始的分配使用最新保存的 Agent、模型与思考参数；多次保存只应用最后一版。只有实际切换成功才追加分界线；空闲时切换失败保留原配置与会话，延后切换失败保留已保存配置供重试。此规则不改变手动新建和断线接续原有的独立对话行为。
- unknown 不重发；等待用户决策不占路由执行槽；不移动已有任务目录、不覆盖任务配置。
- Router 只为识别业务对象、确定归属和判断任务连续性补读资料，判断充分即提交并在宿主接受后结束。已有上下文可作快速入口，但须有适用且充分的项目、需求、任务证据；缺失时定向补读，必要核查后仍有实质歧义才给候选澄清。已知 ID 可直接查阅，包括旧任务和归档资料；72 小时仅限制自动候选列表，旧任务复用的明确指向与连续性由 Agent 判断，宿主保留硬范围、可写性、版本和防重。task_detail 默认提供当前描述、最新输入、近期成果及状态，附材料类型、截断标记和完整来源入口，sourceRef 可续读。
- 澄清回答沿用原 requestId、原始输入、附件与多轮补充，重新进入队尾后再分配；入队顺序保存在现有请求 JSON 的 queuedAt，不改原 createdAt。桌面等待队列与实际调度共用该顺序；原业务输入只展示一次，详情保留完整原生回合。
- 分配时间线按 routerSessionId 或该 Session 内的 routedInputId／router_assign_task 请求 ID 关联历史；不能因旧记录缺少会话归属就将已完成或已取消的请求补进当前时间线，不通过文案或时间猜归属。排队时取消不创建分配卡，已开始的取消和可重试的准备失败保留；旧成功记录有真实请求依据时仍在原会话显示，原始用户气泡与回执保持一致。
- 定位待处理卡片时，入场及高度动画期间持续校正滚动位置，保证操作控件可见；用户主动滚动或切换焦点后停止校正，同版本刷新不抢回滚动位置。
- 分配卡的等待与分配耗时显示在标题栏状态文字右侧。独立 timing 保存实际入队时间、开始时间和累计执行耗时，不使用队列排序值或 updatedAt 推算；完成、失败、取消或等待用户输入时冻结，用户回答重新入队后计新一轮，自动恢复保留本轮计时。沿用现有请求 JSON 和澄清快照，不变更数据库 schema；旧记录缺数据时明确显示未记录。
- 按已确认的 `docs/mockups/router-clarification-choice-2026-11-12/review.html` 及 `docs/mockups/router-cards-draft-2026-11-13/plan.md` 实施：App 与飞书的澄清均使用候选单选加「其他」自填，无可用候选时仍保留「其他」入口；提交时重新校验候选。提交成功后将原问题、候选与回答冻结为“澄清结束”记录，后续不更新。App 排队期间仅显示队列项，实际开始下一轮分配才创建独立新卡片；轮次与快照保存在现有请求 JSON，不改变业务请求身份或数据库 schema。Router 列表仅用卡片展示进度和结果，卡片外的过程、详细回复及消息操作栏只在详情展示。Router 新任务输入文字单独缓存，离页和正常重启后恢复，成功只清理已提交文字，失败及提交期间新草稿保留。
- Router 的补充与澄清仅用于分配，保留问题与回答并直接带入下一轮 Router 输入；初始 hardScope 为 global 不否定用户随后已明确的范围。新建、复用和未投递后的恢复仅发送原业务输入及原附件，不把归属回答或澄清附件交给目标 Agent；已投递的旧格式回执仍按真实账本核对，不重发。归档或只读空间／需求允许只读查阅原文，不允许扫描执行或分配；stale 仅表示摘要过期，不能当作状态未知或反复确认已知范围的理由。
- 按用户于 2026-11-13 确认的范围，澄清选项仅为快捷补充文字：Agent 提供 `label` 与可选 `description`，无需绑定项目、需求或任务对象；保留原文，不根据对象目录过滤或重写。App 与飞书选择后均将 `label` 作为普通 `answer`，沿用原请求继续分配，不直接确定目标。旧卡片的 `objectId`／`optionId` 仅用于找到已展示的文字。请求版本校验、澄清历史、排队、最终分配目标校验及原业务输入投递链路保持不变，沿用现有卡片样式。
- 等待分配的请求只显示在队列中，开始分配后展示卡片，分配成功后保留结果卡；没有 decision 的启动／读取失败及已开始的自动恢复仍保留可见卡片。按用户于 2026-11-12 确认的 `docs/mockups/router-outcome-recovery-2026-11-12/plan.md` 实施：优先有限自动恢复，首次外最多两次，2 秒／8 秒退避，既有提交前断线换会话仍最多一次并计入统一预算。重试与补充沿用原 requestId、输入、附件和来源；unknown 先核对账本，已接收不重发。桌面和飞书复用 Controller，卡片随内容撑开，不保留固定高度或底部空白。
- 新建会话及断线接续按已确认的 `docs/router-session-recovery-plan-2026-11-10.md` 实施：保留单一页面入口，允许更换当前 Router Session，旧历史保留；只有确认尚未提交的连接失效才能自动接续一次，次数持久保存，旧会话工具资格失效。重建失败订阅，不停止共享 Host；继续使用现有表，不做 schema 迁移。
- 复用已有任务时默认按原任务配置继续；本次 Agent、模型、权限或工作目录等配置不同不再触发选择询问。旧版因配置差异等待选择的请求在恢复时重新读取并判断，仍可复用则直接投递；不跳过目标版本与可写性校验。
- 分配不要求 scanId、scopeAssessment 或 reuseAssessment，不因读取记录、引用、资料版本或扫描完成度拒绝分配；目录与分范围快照供按需判断。复用按本轮是否继续、验证或修正具体已有成果或未完事项判断，不按工作类别拆分。保留请求身份与版本、用户硬范围、实时目标类型与可写性、投递版本及防重校验；目标忙时直接排队。路由质量契约以 `docs/router-quality-technical.md` 为准。
- 按用户于 2026-11-16 确认的整体路由方案，自动判断按项目 → 已有需求或新建需求 → 复用任务或新建任务推进。已知归属可直接定位，不要求重复扫描；没有匹配任务不能反推需求不承载目标。补读后仍有影响分配的歧义才澄清，必须给有依据的候选或可行处理选项，沿用纯文字选择与原 requestId 续接。
- router_query 仅保留 catalog、object_detail、task_briefs、task_detail；不再提供 bootstrap、resolve_reference、memories。每轮实际开始时由宿主注入本轮事实、版本、目录版本、快照时间及恢复读取进度；系统提示词集中通用判断规则，不再每轮重复追加场景规则。查询明确对象类型、范围、是否包含下级、资格过滤和分页状态，不能把直属任务空列表当作整个项目没有任务。工具错误返回当前请求状态或同目标恢复参数，不引导调用已删除接口。
- 描述复用 `@huggingface/tokenizers` 与 DeepSeek 官方离线 tokenizer：需求最多 500 token，任务最多 300 token，项目继续最多 200 token。需求描述优先表达目标、功能范围与边界；任务优先复用结合全任务历史生成的任务描述，附带覆盖信息，进展和验收依据另行提供。上限贯通生成、校验、索引与查询，不把局部规格的开头冒充需求全貌。计数放在 worker，资料和快照复用现有 JSON 存储，不新增数据库表；不修改安装 App、凭证、发布脚本。
- 路由反馈按已确认的 `docs/router-agent-review-2026-11-06/feedback-2026-11-09/plan.md` 实施。`reviewStore.ts` 在现有 worker 中保存独立 JSON 反馈与诊断快照，不新增数据库表；反馈不改变分配版本或重新投递业务输入。
- 飞书话题入口按用户已确认的 `docs/feishu-router-plan-2026-11-10.md` 接入现有路由请求；来源元数据保存在现有请求 JSON 中，不新增数据库表。投递前完成话题关联与路由结果展示，保留已有主话题，飞书输入按真实来源记录，unknown 不自动重发。
